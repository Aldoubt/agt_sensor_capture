# v0.1 Motion Hardware Acceptance

Status: **PENDING REAL-HARDWARE RUN**

This run validates acquisition continuity under real robot motion. It is not an odometry-accuracy test.

## 1. Route

Record at least five minutes containing:

- stationary initialization
- straight motion
- several left/right turns
- at least one low-speed section
- normal operating vibration
- open-sky RTK Fixed coverage where practical

Do not design the route to hide GNSS Float/outage events; those states are useful evidence and remain recorded.

## 2. Run

```bash
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch agt_capture_bringup sensors.launch.py
```

In another terminal:

```bash
ros2 launch agt_capture_bringup record.launch.py \
  session_name:=v01_motion \
  output_root:=$HOME/datasets/agt_sensor_capture
```

During/after the run:

```bash
python3 tools/check_rates.py --duration 300 | tee /tmp/agt_v01_motion_rates.json &
RATES_PID=$!
python3 tools/check_timestamps.py --duration 300 | tee /tmp/agt_v01_motion_timestamps.json &
STAMPS_PID=$!
wait $RATES_PID $STAMPS_PID
python3 tools/inspect_bag.py \
  $HOME/datasets/agt_sensor_capture/v01_motion \
  | tee /tmp/agt_v01_motion_bag_report.json
```

## 3. Required PASS criteria

- no camera timestamp rollback or duplicate stamp
- stale/repeated camera timebase count remains 0 during the healthy acceptance window
- no LiDAR/IMU/GNSS timestamp rollback
- no sustained camera frame gaps
- camera remains near 10 Hz throughout motion
- LiDAR remains near 10 Hz and IMU near 200 Hz
- G70 remains near configured 5 Hz even when carrier state changes
- GNSS `CARRIER_FIXED`, `CARRIER_FLOAT`, time validity, hAcc/vAcc and satellite count remain auditable in the bag
- no synchronization component drops a captured camera frame because a timebase sample is stale/repeated
- `session.yaml` continues to state that GNSS is not PPS-bridged in v0.1
